# Vote Project

大众化防作弊投票网站 —— 准入实名 + 投票匿名 + 全量可审计。

## 核心特性

- **准入实名**：注册时同步完成二要素（姓名 + 18 位大陆身份证号）核验，通过即自动成为可投票用户，无需人工审核
- **一人一号**：同一身份证号只能注册一个账号（只存 HMAC-SHA256 摘要并加唯一索引）
- **不存敏感材料**：数据库只保留 `idNumberHash`、加密后的姓名、核验流水号与核验时间；不再保存身份证号明文或身份证照片，也不再有上传目录
- **投票匿名**：每次投票生成全新的基于时间戳的假名，仅用于本次投票记录；业务接口和 PDF 中不含任何实名信息
- **全量可审计**：每场投票都有仅限本场的全量记录，投票成功后强制下载 PDF；投票结束后首次导出会固定 SHA-256 摘要，之后每次导出都会校验并标注是否一致
- **防重复投票**：一个实名身份（账号）每场投票只能投一次，服务端强校验投票阶段、时间窗口、邀请资格、选项归属、单选/多选、弃权互斥与重复提交
- **两种参与模式**：公开链接（OPEN_LINK）与邀请制（INVITE_ONLY），见下
- **配置灵活**：支持单选/多选，创建者可在投票开始前决定结果是否实时公开

## 两种参与模式

### 模式 A：公开链接（OPEN_LINK）

- 创建即开始，创建时必须选择一个固定的结束时间。
- 创建者可以提前结束；也可以等待结束时间到达后自动结束。
- 任何已核验用户拿到链接都能参与，每人限投一次。
- 结束后，所有已登录用户都可以查看结果分布和完整版 PDF。

### 模式 B：邀请制（INVITE_ONLY）

- 创建后是「未开始」（DRAFT），创建者先配置受邀人，再手动开始。
- 邀请方式：
  - **按用户名邀请**：精确匹配已注册用户名，长期有效，直到被接受或移除。
  - **一人一链接**：适合尚未注册的人，7 天有效、单次使用、可撤销；链接只在生成后立即展示，离开页面后无法再次查看未使用的链接（可重新生成）。
- 开始后不能再新增受邀人；已投票的受邀人不能移除，未投票的可以移除。
- 创建者自己也需要被邀请才能投票。
- 所有「未被移除且已绑定用户」的邀请人都投票后，投票自动结束。
  - 未接受的**用户名邀请**会阻塞自动结束，需要创建者催办或移除。
  - 未接受的**一人一链接**不阻塞自动结束。
- 时长从创建者点击「开始」的时刻起算，而不是创建时刻。

### 时间语义

- 所有时间均以 UTC 存储与展示。
- 模式 A：`startAt` = 创建时刻，`endAt` = 创建者选择的固定结束时间。
- 模式 B：`startedAt` 为空时一律视为「未开始」，不受创建时占位 `endAt` 影响；开始后写入 `startedAt`，`endAt = startedAt + durationMinutes`。
- 「进行中」的判定以服务端 `phase` 为准（`DRAFT` / `LIVE` / `ENDED`），前端不自行推断。

## 实名与隐私

### 注册与核验

- 注册需要：用户名、密码（≥ 6 位）、真实姓名、18 位大陆身份证号，并同意实名条款。
- 用户名不得等于身份证号；同一身份证号不可重复注册。
- 核验通过 → `APPROVED`，可创建和参与投票。
- 核验服务不可用 → 账号以 `PENDING_VERIFICATION` 建号，可稍后在「账号」页调用 `POST /api/auth/reverify` 重新核验；核验失败（姓名与身份证号不匹配）不会建号。
- 历史用户的实名材料已由清理脚本移除；`uploads/` 不再接收任何材料。

### 匿名的边界

`Ballot` 不存 `userId`，只存 `pseudonym`；但 `UserVoteHistory` 为了防止重复投票，存了 `(userId, voteId, ballotSequenceNumber)`。

也就是说：

- 通过 API 和 PDF 的使用者**无法**把假名和真人对应起来
- 直接拿到数据库（管理员、备份、云厂商）的人**可以**用 `ballotSequenceNumber` 把 `userId → ballot → pseudonym` 关联起来

这是当前架构的已知边界。系统不对外宣称「连 DBA 都无法关联」。

### 名单可见性

| 阶段 | 模式 A | 模式 B |
|---|---|---|
| 未开始（DRAFT） | — | 受邀者可见完整实名与接受状态；创建者可管理邀请 |
| 进行中（LIVE） | 只列已投票者，姓名脱敏（张\*三） | 仅创建者可见谁已投/未投；受邀者看不到投票状态 |
| 已结束（ENDED） | 已登录用户可见脱敏名单 | 本场受邀者/创建者/管理员可见完整实名，不标注投票状态 |

模式 B 的小名单存在推断风险：即使不标注投票状态，人数很少时仍可能通过「谁在场」推测个别选择。这是产品层面的已知限制。

### 结果可见性

- 投票进行中，页面只显示「已投 N / M 人」；结果是否实时公开由创建者的 `resultsPublicDuringVote` 决定（默认关闭，开始后不可修改）。
- 模式 A 结束后对登录用户公开分布；模式 B 只对本场参与者、创建者、管理员公开。

## 弃权规则

- 每场投票自动附带系统选项「弃权」，固定在最后，不能删除或重命名。
- 弃权计为一票，百分比分母包含弃权。
- 弃权与其它选项互斥：多选时选中弃权会清空其它选项，选中其它选项会清空弃权。
- 必须显式选择后才能提交；系统不会自动代为弃权。
- 结果页最多显示「未形成多数」等描述，不宣称胜者。

## 全量记录 PDF

- 投票成功后强制下载本场 PDF；也可在「我的投票」重新下载。
- PDF 正文为中文，内置 Noto Sans SC（OFL）常规与粗体，导出时只嵌入本次用到的字形。
- 进行中：非创建者/管理员下载的 PDF **隐藏选项和票数**，只保留序号、假名、提交时间、摘要。
- 进行中：创建者/管理员可以下载完整版，便于主办方核对。
- 结束后：PDF 为完整记录。
- 访问控制：
  - 创建者、参与者、管理员：随时可下载
  - 其他已核验用户：投票结束后可下载
  - 未核验账号：不可下载
- 摘要规则：
  - 进行中不封存摘要，PDF 标注为实时快照
  - 结束后首次导出：计算 SHA-256 写入 `Vote.auditHash` / `Vote.auditRecordedAt`
  - 之后每次导出：重新计算并对比，PDF 标注「记录与封存摘要一致 / 不一致」
  - 摘要只用于发现「导出后被改动」，不等同于区块链式不可篡改

## 管理员

- `/admin/users` 只读展示用户核验信息（用户名、姓名、状态、核验时间、注册时间）。
- 唯一写操作是「重置密码」，返回一次性临时密码，关闭弹窗后无法再次查看。
- 旧的身份证照片审核页已删除。

## 威胁模型

这套系统**承诺**防住：

- 同一个人用同一个身份证号注册多个账号反复投票
- 事后抵赖：每场投票都有可导出、带摘要校验的全量记录
- 部分内部篡改：投票结束后记录被修改时，导出的 PDF 会显示摘要不一致

**不承诺**防住：

- 组织化刷票、收买投票、一人使用他人真实身份注册
- 设备指纹、IP、浏览器指纹级别的识别
- 拥有数据库直接访问权限的人把假名还原成真人
- 极小规模邀请制投票中的社交推断

## 环境变量

| 变量 | 用途 |
|---|---|
| `DATABASE_URL` | SQLite 连接串 |
| `JWT_SECRET` | JWT 签名密钥 |
| `ENCRYPTION_KEY` | 姓名等敏感字段的加密密钥 |
| `ID_HASH_SECRET` | 身份证号 HMAC 摘要密钥（不设置时回退到 `ENCRYPTION_KEY`） |
| `IDENTITY_PROVIDER` | 二要素核验提供方：`mock` 或 `http` |
| `MOCK_ID_NUMBERS` | `mock` 模式下允许通过的身份证号，逗号分隔 |
| `IDENTITY_API_URL` / `IDENTITY_API_KEY` | `http` 模式下核验服务的地址与密钥 |
| `CORS_ORIGIN` | 允许的跨域来源，逗号分隔；同域部署不需要设置 |

> `ID_HASH_SECRET` 一旦用于生产环境就不要再更换，否则历史用户的 `idNumberHash` 将无法与新注册用户去重。
> 生产环境必须显式设置 `IDENTITY_PROVIDER`；未设置时后端拒绝启动，避免误用 mock 核验。

生产部署（单台 VPS + 已有 Nginx + systemd，含备份、发布、回滚）见 [`docs/deploy-production.md`](docs/deploy-production.md)。

## 已知限制

- `UserVoteHistory.ballotSequenceNumber` 与 `Ballot.sequenceNumber` 可在数据库层关联，见「匿名的边界」。
- 模式 B 的小名单存在投票状态推断风险，见「名单可见性」。

## 主要功能流程

1. 注册并完成二要素核验（通过即 `APPROVED`）
2. 创建投票，选择公开链接或邀请制
3. 公开链接直接分享；邀请制先按用户名邀请或生成一人一链接，再手动开始
4. 参与者在时间窗口内投票，每次生成新假名，仅能投票一次
5. 投票成功后强制下载本场全量记录 PDF（进行中隐藏选项与票数）
6. 结束后查看结果、名单与完整版 PDF
